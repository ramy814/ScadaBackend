# 04 — خارطة الطريق والحالة الحالية

> هذه الوثيقة تقول بصراحة ما تم بناؤه وما يحتاج قراراً أو تجربة على الخادم.
> اللوحة السابقة تبقى تعمل كما هي؛ لم يُعدَّل فيها أي ملف.

## ما يحتاج متابعة قبل الاعتماد الكامل

| البند | السبب | الإجراء |
|---|---|---|
| التشغيل على Oracle الحقيقي | لم يكن متاحاً أثناء البناء؛ التحقق تم على SQLite يحاكي المخططات | تشغيل على قاعدة تجريبية ومراجعة كل شاشة، خصوصاً استعلامات `TO_DATE` و`SDO_*` |
| دخول SSO | الحزمة الخاصة `mog/project-helper` غير متاحة خارج الخادم | تثبيتها على الخادم واختبار الدخول والخروج |
| الصور (الآبار) | تُقرأ وتُكتب على تخزين النظام القديم | ضبط `LEGACY_MEDIA_ROOT` إلى `storage/app/private` في القديم مع صلاحية كتابة |
| GeoServer | بيانات الدخول من `.env` فقط | ضبط `GEOSERVER_USERNAME/PASSWORD` على الخادم |
| الفروق المقصودة عن القديم | 1) طوابير المراجعة لا تُخفي المعلّق خارج الفترة. 2) قرار المراجعة النهائي مقفل في الخلفية. 3) وكيل البلاط محمي بالدخول. 4) استعلامات SQL الخام ذات `IN (...)` في الآبار والمحابس مقسّمة على دفعات من 1000 (خطأ Oracle ORA-01795 عند تجاوز 1000 جرد سولار) | موثّقة هنا؛ يجب تطبيق (2) و(4) في القديم أيضاً |

## فرص جديدة (تحتاج قرار عمل + باك اند، غير منفذة)

1. **تتبع إصدارات تطبيقي الآبار والمحابس**: endpoint حضور مماثل لتطبيق السائق في الباك اند الحالي + تحديث التطبيقين؛ عندها يعرض دليل التطبيقات والنظرة العامة تبنّي الإصدارات لكل التطبيقات.
2. **سجل تدقيق موحد**: كتابة أحداث الآبار والمحابس والصلاحيات في `AUDIT_LOGS`.
3. **إغلاق تقارير الصيانة من الويب**: يحتاج تحديد من يملك صلاحية الإغلاق.
4. **صحة الخدمات**: فحوص دورية لـ Oracle وGeoServer وSMS تُخزّن وتُعرض في المنصة.
5. **نقل واجهات الموبايل** إلى المنصة: قرار منفصل لاحق؛ لا يلزم الآن لأن المنصة تقرأ نفس قاعدة البيانات.

## خطة الإطلاق دون المساس بالإنتاج

1. نشر المنصة على مضيف مستقل (مثلاً `platform.mogaza.org`) بـ `APP_KEY` وكوكي جلسة مختلفين.
2. `composer install` مع إضافة مستودع المسار `../mog-package` ثم `composer require mog/project-helper` (حزمة SSO الخاصة)، وتسجيل عميل SSO للمنصة أو استخدام نفس العميل بعنوان رجوع جديد.
3. `.env`: اتصال Oracle نفسه، `APP_TIMEZONE` مطابق للنظام القديم، `MOG_PERMISSIONS_ADMIN_USER_IDS`، `LEGACY_MEDIA_ROOT` لمسار `storage/app/private` في النظام القديم، إصدار تطبيق السائق.
4. `npm ci && npm run build`. **لا يوجد `php artisan migrate`** — المنصة لا تملك جداول.
5. تجربة مع مشرفي الأسطول بالتوازي مع اللوحة القديمة؛ نفس البيانات ونفس الصلاحيات.
6. بعد اكتمال كل وحدة P1/P2: تحويل روابط اللوحة القديمة إلى المنصة، ثم إزالة صفحات الويب القديمة (تبقى واجهات الموبايل).

> طالما يعمل النظامان معاً: أي تغيير في قاعدة عمل يجب تطبيقه في الاثنين.
