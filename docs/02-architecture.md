# 02 — المعمارية الجديدة: المعلومات، التنقل، وإدارة التطبيقات المتعددة

## 1. قرار المنتج الأساسي

**المنصة = مساحات عمل للتطبيقات + خدمات منصة مشتركة + نظرة تنفيذية واحدة.**

لا نصمم حول جداول قاعدة البيانات ولا حول "أنظمة" منفصلة، بل حول ثلاثة أسئلة يسألها المسؤول كل صباح:
1. **ما الذي ينتظر قراري الآن؟** ← النظرة العامة (صندوق انتباه موحد).
2. **كيف يعمل التطبيق الميداني X؟** ← مساحة عمل التطبيق.
3. **من يملك الوصول، وهل المنظومة تعمل؟** ← المنصة.

## 2. مبادئ التعايش مع النظام الحالي (لا مساس بالإنتاج)

| المبدأ | التطبيق |
|---|---|
| مشروع مستقل | تطبيق Laravel منفصل في `platform/` بـ `composer.json` و`.env` و`APP_KEY` واسم كوكي جلسة خاص، يُنشر على مضيف مستقل (مثلاً `platform.mogaza.org`). |
| لا تعديل على النظام القديم | لا يُعدّل أي ملف خارج `platform/`. واجهات الموبايل تبقى في النظام القديم ولا تُنسخ. |
| لا تغيير في المخطط | لا migrations على جداول Oracle المشتركة. مخطط الاختبار فقط في `tests/Schema` ويُحمّل على SQLite في الذاكرة. |
| قواعد العمل منقولة لا مُخترعة | النماذج والمستودعات والخدمات تُنقل من القديم إلى وحدات المنصة مع اختباراتها، ثم تُصلح الثغرات الموثّقة (مثل عدم قابلية تغيير المراجعة). |
| نفس نموذج الصلاحيات | `SYSTEM_PERMISSIONS` + نطاق Oracle للأسطول، بنفس دلالات الفشل المفتوح/المغلق. |
| احترام الإيقاف الطارئ | المنصة تقرأ `SYSTEM_OPERATIONAL_STATES` وتعرض صفحة الصيانة لمساحات العمل، وتبقي "المنصة ← التشغيل" متاحة لمديري الصلاحيات. |

**تبعات:** طالما يعمل النظامان معاً، أي تغيير قاعدة عمل يجب أن يُطبّق في كليهما. خطة الإحلال: عند تكافؤ كل وحدة تُحوّل روابطها في القديم إلى المنصة، ثم تُزال صفحات الويب القديمة. تبقى واجهات الموبايل في القديم حتى قرار منفصل.

## 3. المعمارية التقنية: Modular Monolith

```
platform/app/
├── Platform/                 # النواة المشتركة
│   ├── Applications/         # سجل التطبيقات (config/applications.php) + ApplicationRegistry
│   ├── Access/               # SystemPermissionRepository, AccessService, middleware
│   ├── Identity/             # SSO adapter + local dev login, MogSsoUser
│   ├── Operations/           # حالة التشغيل العامة (قراءة/تعديل)
│   ├── Audit/                # قراءة audit_logs
│   ├── Overview/             # ExecutiveOverviewService (يجمع من الوحدات عبر عقود)
│   └── Support/              # OracleReadiness, Navigation, Inertia props
└── Modules/
    ├── Fleet/  { Models, Repositories, Services, Http/{Controllers,Requests}, FleetModule.php }
    ├── Wells/  { ... , WellsModule.php }
    └── Valves/ { ... , ValvesModule.php }
```

- كل وحدة تعرّف `Module` بسيط: المفتاح، التطبيق المرتبط، مسار المسارات، **عناصر التنقل**، و**مزوّد مؤشرات النظرة العامة** (`attention()`).
- النظرة العامة لا تستعلم جداول الوحدات مباشرة؛ تسأل كل وحدة مصرّح بها عن "عناصر الانتباه" الخاصة بها.
- إضافة تطبيق رابع = وحدة جديدة + سطر في `config/applications.php`. لا تعديل على الهيكل.
- الطبقات داخل كل وحدة كما في قواعد المشروع: Controller رفيع ← FormRequest ← Service ← Repository ← Model.

## 4. معمارية المعلومات الجديدة

```
◉ النظرة العامة                         /
│   صندوق الانتباه (عبر التطبيقات) · نبض التطبيقات · حالة التشغيل
│
├─ ▣ تطبيق السائق — الأسطول               /fleet
│   العمل اليومي
│     • المراجعة         /fleet/reviews          (صندوق: بانتظار المراجعة · توضيح · يدوي · الكل)
│     • الرحلات الحية    /fleet/live             (رحلات بلا ended_at + حداثة التتبع)
│     • تفاصيل الرحلة    /fleet/trips/{id}       (درج جانبي من المراجعة + صفحة كاملة)
│   التطبيق
│     • التثبيتات والإصدارات /fleet/app          (تبنّي تطبيق السائق)

│   الإعدادات
│     • الكتالوجات       /fleet/catalogs         (المواقع + أنواع المهام في تبويبين)

├─ ▣ تطبيق مفتشي الآبار — الآبار           /wells
│   العمل اليومي
│     • اليوم            /wells                  (آبار بلا قراءة اليوم، آخر القراءات)
│     • البلاغات         /wells/signals          (صندوق وارد: غير مقروء/الكل)
│     • القراءات         /wells/readings         (سجل + تقرير الإنتاج)
│     • السولار          /wells/diesel           (الجرد + الشهري)
│   الأصول
│     • الآبار           /wells/assets           (جدول + خريطة كتبديل عرض)
│   الفرق الميدانية
│     • الفرق والمفتشون  /wells/field            (تبويبان)

│     • أنواع البلاغات   /wells/settings/signal-types
│
├─ ▣ تطبيق SCADA — المحابس                /valves
│   العمل اليومي
│     • اليوم            /valves                 (تقارير صيانة مفتوحة، عمليات اليوم)
│     • الصيانة          /valves/maintenance     (تقارير الصيانة بحالاتها)
│     • العمليات         /valves/actions         (سجل الإجراءات)
│     • الخريطة          /valves/map
│   الفرق الميدانية
│     • الفرق والمفتشون  /valves/field

      • المستخدمون والصلاحيات  /platform/access
      • التشغيل              /platform/operations  (مفتاح الإيقاف الطارئ — منفصل عن الصلاحيات)
      • سجل التدقيق          /platform/audit
      • التطبيقات            /platform/applications (دليل التطبيقات وعقودها وإصداراتها)
```

### لماذا هذا الترتيب
- **"العمل اليومي" أولاً** في كل مساحة: الطوابير التي تتطلب قراراً (مراجعة، بلاغات، صيانة) قبل السجلات والإعدادات.
- **دمج الشاشات الصغيرة المتجانسة**: الفرق + المفتشون في صفحة "الفرق الميدانية" بتبويبين؛ المواقع + أنواع المهام في "الكتالوجات"؛ جدول الآبار + الخريطة في "الأصول" كتبديل عرض.
- **فصل الخطير عن الروتيني**: مفتاح الإيقاف الطارئ في صفحة "التشغيل" المستقلة، وليس أسفل محرر الصلاحيات.
- **تسمية حسب المعنى**: "البلاغات" بدل "الإشعارات"، "العمليات" بدل "التقارير" لسجل المحابس.

## 5. نظام التنقل

```
┌────┬──────────────────┬───────────────────────────────────────────────┐
│ ◉  │ تطبيق السائق      │  الأسطول › المراجعة › رحلة #1842   [⌘K بحث] ☾ ع/EN 👤│
│ ▣  │  العمل اليومي     ├───────────────────────────────────────────────┤
│ ▣  │  • المراجعة  (12) │                                               │
│ ▣  │  • الرحلات الحية  │            محتوى الصفحة                        │
│    │  التطبيق          │                                               │
│ ⚙  │  • التثبيتات      │                                               │
└────┴──────────────────┴───────────────────────────────────────────────┘
 شريط    شريط سياقي          شريط علوي: مسار التنقل + بحث + أدوات
 التطبيقات
```

| السؤال | الإجابة في الواجهة |
|---|---|
| أين أنا؟ | مسار التنقل (breadcrumbs) + العنصر النشط في الشريط السياقي + عنوان الصفحة |
| أي تطبيق أدير؟ | شريط التطبيقات (أيقونة + لون هوية) + رأس الشريط السياقي باسم التطبيق ولونه |
| ماذا أستطيع أن أفعل؟ | زر الإجراء الأساسي في رأس الصفحة + أرقام الطوابير في الشريط + لوحة الأوامر |

- **شريط التطبيقات** (Rail): يظهر فقط ما يملك المستخدم صلاحيته. التبديل بين التطبيقات نقرة واحدة، ويحتفظ كل تطبيق بآخر صفحة زارها المستخدم فيه (`sessionStorage`).
- **الشريط السياقي**: مجموعات قابلة للطي (progressive disclosure)، أرقام للطوابير القابلة للتنفيذ فقط.
- **لوحة الأوامر** (`Ctrl/⌘ + K`): انتقال لأي صفحة مصرح بها، وفتح رحلة برقمها `#1842`. يتوسع لاحقاً للبحث في الآبار والمحابس.
- **الجوال/التابلت**: الشريطان يتحولان إلى درج منزلق من جهة البداية؛ الجداول تتحول إلى بطاقات مكدسة تحت 720px.

## 6. استراتيجية إدارة التطبيقات المتعددة

**سجل التطبيقات** (`config/applications.php`) هو مصدر الحقيقة لكل تطبيق Flutter:

| الحقل | مثال (تطبيق السائق) | الاستخدام |
|---|---|---|
| `key` | `fleet` | يطابق `SYSTEM_PERMISSIONS.SYSTEM_KEY` |
| `name` | تطبيق السائق / Driver app | الهوية في الواجهة |
| `domain` | الأسطول / Fleet | اسم المساحة |
| `accent` | `blue` | لون الهوية (رمز تصميم) |
| `platforms` | Android | معلومة للدليل |
| `auth` | SMS OTP · توكن `driver` | عقد المصادقة |
| `api_prefix` | `/api/driver` | للتوثيق والدليل |
| `release` | `config('driver_app.latest_*')` | الإصدار المعتمد (للسائق فقط حالياً) |
| `telemetry` | `driver_app_installations` | هل يوجد تتبع تثبيتات؟ |

- كل تطبيق له **هوية بصرية** (لون + أيقونة) تظهر في الشريط والرأس ومسار التنقل وعناصر النظرة العامة.
- **الوظائف المشتركة لا تتكرر داخل التطبيقات**: الصلاحيات، التشغيل، التدقيق، ودليل التطبيقات مركزية في "المنصة".
- **الوظائف الخاصة تظهر فقط حيث تنتمي**: الإدخال اليدوي للأسطول فقط، التقارير الشهرية للسولار للآبار فقط، الخريطة الجغرافية المكانية للمحابس فقط.
- **دليل التطبيقات** يعرض لكل تطبيق: المصادقة، عقد الـ API، الإصدار المعتمد، وتغطية التتبع — ويقول صراحة "غير متوفر" لتطبيقي الآبار والمحابس اللذين لا يرسلان بيانات إصدار.

## 7. الصلاحيات في المنصة

| الطبقة | المصدر | السلوك |
|---|---|---|
| دخول المنصة | SSO (`admin` guard) + أي صلاحية نظام أو نطاق مساعد | يُرفض من لا يملك أي وصول |
| دخول مساحة تطبيق | `SYSTEM_PERMISSIONS` (`fleet`/`wells`/`valves`) | فشل مفتوح إذا Oracle غير متاح (كالقديم) |
| مراجعة رحلات الأسطول | `fleet` + نطاق Oracle `ACCESS_TYPE IN (2,3)` | فشل مغلق |
| الإدخال اليدوي | نطاق Oracle `ACCESS_TYPE IN (1,3)` | فشل مغلق، لا يمنح مساحة الأسطول |
| حذف القراءات/الجرد | `wells.readings.delete` / `wells.diesel-inventories.delete` | فشل مغلق، يتطلب `wells` |
| المنصة (صلاحيات/تشغيل) | `MOG_PERMISSIONS_ADMIN_USER_IDS` | خارج البيئة المحلية فقط هؤلاء |

الواجهة تستهلك **أعلام إجراءات من الخادم** (`can.review`, `can.delete`...) ولا تستنتج الصلاحيات.

## 8. رحلات المستخدم الرئيسية (قبل/بعد)

| الرحلة | القديم | الجديد |
|---|---|---|
| مراجعة رحلة | البوابة ← لوحة الأسطول ← صف ← صفحة تفاصيل ← قرار ← عودة وإعادة الفلاتر | النظرة العامة ("12 بانتظار المراجعة") ← صندوق المراجعة ← فتح درج التفاصيل ← قرار من الدرج ← الصف التالي تلقائياً |
| الانتقال بين الآبار والمحابس | قائمة الآبار ← البوابة ← المحابس | نقرة على أيقونة المحابس في الشريط |
| معرفة الآبار بلا قراءة اليوم | تصدير تقرير الإنتاج والبحث عن "غير مدخلة" | عنصر انتباه في النظرة العامة + بطاقة في "اليوم" |
| إيقاف الأنظمة طارئاً | قسم مطوي أسفل صفحة الصلاحيات | المنصة ← التشغيل (صفحة واحدة، حالة واضحة، تأكيد مزدوج) |
| فتح رحلة برقمها | البحث داخل لوحة الأسطول | `⌘K` ← `#1842` |
