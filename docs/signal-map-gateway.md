# بوابة GeoServer لتطبيق الإشارات والمفتش

يدعم المسار الموجود الآن توكنات التطبيقين دون تغيير رابط Flutter:

```http
GET /api/map/tiles/{zoom}/{x}/{y}.png
Accept: image/png
Authorization: Bearer <APP_ACCESS_TOKEN>
```

## طريقة التحقق

- مشروع المفتش: طلب قراءة إلى `HIRAF_PROFILE_URL`، افتراضيًا
  `https://apps.mogaza.org/api/account-follow-up/profile`.
  يلزم رد ناجح و`status: true` و`data.oid` موجب؛ إذا ورد `is_active` يجب أن يكون فعالًا.
- تطبيق الإشارات: طلب قراءة إلى `SIGNAL_MAP_AUTH_URL`، افتراضيًا
  `https://mapps.mogaza.org/api/get_signal_statistics`.
  يلزم رد ناجح و`status: true` مع حقول العدادات الثلاثة الصحيحة.
- تم اختيار نقطة الإحصائيات لأنها نقطة محمية مستخدمة فعليًا في تطبيق الإشارات؛
  اختبار مباشر بتاريخ 2026-10-25 أثبت رفض التوكن المفقود والخاطئ بـ401، وقبول
  توكن إشارات صحيح بـ200. لا تُستخدم بيانات الدخول وكلمة المرور داخل البوابة.
- تُرسل الطلبات بهيدر Bearer، مع مهلة اتصال 3 ثوان وطلب 8 ثوان، دون اتباع تحويلات HTTP.
- تُحفظ نتيجة القبول فقط لمدة 60 ثانية بمفتاح مشتق من SHA-256 للتوكن وعناوين
  التحقق. لا يُحفظ التوكن بنص صريح ولا بيانات المستخدم أو رد الإحصائيات.
  لا تُحفظ نتائج الرفض أو أعطال الخدمات. قد يستمر قبول جلسة أُلغيت حتى انتهاء هذه المدة.
- نجاح أحد المصدرين يكفي للخرائط فقط. هذا لا يمنح جلسة محلية أو صلاحية على
  واجهات Fleet/Wells/SCADA الأخرى، وتبقى وسائط عزل التوكنات فيها كما هي.

المكونات: `AuthenticateMapClient` ← `MapClientAuthService` ← `MapClientRepository`.
خدمة `GeoServerTileService` والكونترولر الحاليان يستمران في جلب الصورة وإعادتها.

## الاستجابات والقيود

- `200` مع بايتات الصورة و`Content-Type: image/png`، دون تغليف الصورة داخل JSON.
- `401` إذا لم يوجد Bearer token أو رفضته جهتا التحقق.
- `503` مع `Retry-After: 30` إذا تعذر حسم المصادقة بسبب عطل خدمة خارجية أو رد غير صالح.
- `404` للإحداثيات أو مستويات التكبير خارج النطاق بعد المصادقة.
- `502` إذا لم يعد GeoServer صورة صالحة وفق تحقق الخدمة الحالي.
- `429` عند تجاوز 600 طلب في الدقيقة. تحديد المعدل يسبق التحقق الخارجي.
- الإيقاف التشغيلي العام يسبق المصادقة ويعيد عقد الصيانة الحالي؛ لا تُحذف جلسات أو بيانات جوال.
- الطبقة ثابتة: `mog:gaza general map`، مصفوفة `EPSG:900913`، ومستويات 11–17.
  حدود غزة الحالية لم تتغير، ولا يقبل العميل اختيار طبقة أو عنوان GeoServer.
- بيانات GeoServer تبقى ضمن إعدادات السيرفر؛ لا تُرسل إلى Flutter.

## الرفع إلى السيرفر

التغيير مطبق محليًا، ولم يُنشر تلقائيًا إلى `scada.mogaza.org`.

1. ارفع ملفات التعديل الجديدة والمعدلة من هذا المشروع معًا؛ المسار واسم الراوت لم يتغيرا.
2. احتفظ بإعدادات `HIRAF_PROFILE_URL` و`GEOSERVER_*` الحالية. الإعداد الجديد الاختياري:

   ```dotenv
   SIGNAL_MAP_AUTH_URL=https://mapps.mogaza.org/api/get_signal_statistics
   ```

   له القيمة الافتراضية نفسها في `config/services.php`، ولا يلزم تعديل إعدادات Flutter.
3. امسح كاش Laravel بعد الرفع لأن middleware والإعدادات تغيرا:

   ```sh
   composer dump-autoload --optimize
   php artisan optimize:clear
   php artisan route:list --path=api/map/tiles -v
   ```

   إذا كان النشر يستخدم كاش الإعدادات/المسارات، أعد بناءه وفق آلية النشر الحالية.
   وأعد تحميل PHP/OPcache إذا كانت بيئة الإنتاج تتطلب ذلك.
4. تحقق من البلاطة `/api/map/tiles/13/4880/3340.png` بتوكن إشارات صحيح وتوكن
   مفتش صحيح، ثم بتوكن غير صحيح. يلزم PNG/200 للصحيح و401 للخاطئ.
5. افتح التطبيق الحالي واضغط «إعادة المحاولة»، ثم اختبر التنزيل والأوفلاين.

لا توجد migrations أو تعديلات Oracle أو تغيير لتسجيل دخول أي من التطبيقين.

## التحقق المنفذ

- اجتازت `MapTileTest` و`MobileTokenAbilityTest` و`SystemOperationalStateTest`
  جميعها: 40 اختبارًا و725 تأكيدًا.
- اجتاز Laravel Pint تنسيق الملفات المعدلة.
- اختُبرت الخدمة الجديدة محليًا بتوكن إشارات حقيقي وبطلبات حقيقية إلى خدمات
  المصادقة وGeoServer: قُبل التوكن وأُعيد PNG/200 بحجم 109756 بايت، مع توقيع PNG صحيح.
- اختُبر توافق المفتش باختبارات استجابات تطابق عقد تطبيقه؛ لم يتوفر حساب مفتش
  صالح لإجراء اختبار إنتاجي حيّ له. يجب التحقق منه بعد الرفع كما أعلاه.
- نجاح الخدمة محليًا لا يعني أن تعديلها منشور على بوابة الإنتاج بعد.
